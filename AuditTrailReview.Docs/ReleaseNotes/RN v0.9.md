## 🚀 Release v0.9 – GxPAuditTrailReview

**Release Date:** 16-Nov-2026

Version 0.9 builds on the v0.8 release. This draft is updated as work on the version progresses.

---

### ✨ New Features

- Added a nightly database backup to the PostgreSQL Docker flavor (`docker/docker-compose.postgres.yml`). A new `backup` service runs `pg_dump` every day at 03:00 (time zone configurable through `TZ`), writes gzipped SQL dumps to `./backups/daily` and deletes dumps older than 14 days (`BACKUP_KEEP_DAYS`). Weekly and monthly retention is disabled. The compose file documents how to restore a dump and how to run a backup on demand.
- Added a step-by-step walkthrough for deploying the application to a Mikrus VPS over SSH with Docker (`CICD/VPS and Docker.md`).
- Scan Details now links the uploaded file name to a download of the original file. The original bytes are stored in a new `ScanFile` table going forward; scans processed before this release have no stored copy and show "(original file not available)" instead of a link.
- Added a General Settings page (`Admin panel → Application Settings → Edit General Settings`) for the date/time display format (e.g. `26-Oct-26 21:32`, a US style, ISO, and other regional options) and the display time zone used throughout the application, independent of the existing [C3] working-hours time zone. Every date/time shown on screen or exported to Excel -- including audit-trail record and review timestamps, which previously always showed raw UTC regardless of any time zone setting -- now goes through this one configurable setting, and a change takes effect immediately without restarting.
- Every page that edits a single tracked record now has its own "📜 Audit trail" tab, showing just that record's own create/update/delete history instead of the single combined `Log → Audit trail log` list: a system (`System/Details`), a scan (`Scan/Details`), a system type (`Config Panel → System type`), a user account, and a role (both under `Admin Panel`). This only covers changes made from this release onward -- a record's history from before this feature existed can't be retroactively attributed to it, so its tab may show fewer entries than the combined log does for the same record.
- The Rule-Based Review Engine page (`Config Panel → Rule-based review engine`) gained a "📜 Audit Trail" tab with separate **Rule Configuration** and **Engine Settings** sub-tabs, so rule-enablement changes and engine-setting changes can each be reviewed on their own, independent of the rest of the audit trail.
- Each of the four Application Settings edit pages (Security Policy, Email, General, AI) gained its own "📜 Audit Trail" tab, showing only that section's own change history.
- The AI Analysis page (`Admin Panel → AI Analysis`) gained a "📜 Audit Trail" tab tracking specifically who enabled or disabled AI review for manually uploaded scans, and when -- separate from any other engine-setting change.
- Admins can now deactivate a user account (`AdminPanel → Users → Edit`, "Deactivate this account") to block sign-in without deleting them, reusing Identity's existing `LockoutEnd`/`LockoutEnabled` columns (no schema change). Guards prevent deactivating your own account or the last remaining active Admin, and the change is audit-logged. Repeated failed logins past a configurable threshold (default raised from 3 to 5) now escalate into that same indefinite deactivation instead of Identity's short self-resolving lockout, except for the sole remaining active Admin.
- Scan Details now shows "Uploaded by" (in place of "File type") for scans uploaded through the WebApp -- blank for FTP/API ingestion -- and the Dashboard's "Latest 5 scans" is now "My Latest 5 scans", filtered to the signed-in user.
- The AI Analysis tab can now store the OpenAI API key directly in the database (encrypted at rest with AES-256-GCM) instead of only reading it from configuration, and lets an admin pick the chat model used for every AI call (`gpt-4o-mini` or `gpt-5-mini`). Rotating the key or switching models takes effect immediately, with no redeploy; the key's ciphertext is kept out of the audit trail even for a key-only change.
- Added a new component, `AuditTrailReview.McpServer`, exposing scan/system data to a chat client (e.g. Claude) over the Model Context Protocol (MCP), so QA can explore audit-trail data conversationally instead of writing SQL or clicking through the web UI. It ships two read-only tools today -- `list_systems` and `list_scans` (optionally filtered by system, capped at 200 rows per call) -- and is strictly read-only by construction: it never calls `SaveChanges`, so there is no path through this component that can change data, unlike the Integration Hub API. It's a separate component on purpose, kept apart from the Integration Hub API's integrator-facing, write-capable surface (see ADR-0010). Runs over HTTP (Streamable HTTP transport, stateless mode) and ships its own `Dockerfile`; `docker/docker-compose.postgres.yml` includes it as the `mcp` service on port 8082 and it supports the PostgreSQL flavor.
- `AdminPanel -> Settings` gained two new tabs, "API" and "MCP", for managing the Integration Hub API's and the MCP server's authentication keys: generate a new named key (shown once -- it's stored only encrypted, AES-256-GCM via the same `ApiKeyProtector` already used for the OpenAI key above, and can never be redisplayed) and revoke one (soft, never deleted, so its audit history stays intact). Each tab has its own paginated Audit Trail sub-tab and Excel export sheet, matching the pattern of every other Settings tab. The two tabs draw from completely separate tables (`dbo.ApiKeyCredential` and `dbo.McpApiKeyCredential`) -- a key generated on one tab can never authenticate the other service. This replaces the previous static `ApiKeyAuth:Keys`/`McpAuth:Keys` lists in each service's own `appsettings.json`; **both services now additionally require `Security:EncryptionKey`** (the same master key the WebApp and Worker Service already use) to decrypt and validate the keys this generates, and **any caller still using the old shipped placeholder key will get `401` after upgrading** until an admin generates a real key and redistributes it.
- Added session timeout and automatic logoff. The Security tab (`Admin Panel → Settings`) gained an idle timeout (default 20 minutes), a maximum session length (default 10 hours) and a sign-out warning (default 2 minutes before timeout); the browser shows a "You'll be signed out in …" dialog and then signs the user out automatically. "Remember me" has been removed, so sessions are never persistent, and password changes, role changes and deactivations now end a user's other sessions within about a minute (previously up to 30). Background notification polling no longer keeps an idle session alive. **Requires database script `ATR 0.38`** (adds three columns to `SecuritySettings`); any session open at upgrade time is signed out once.
- **Close review & sign** and **Reopen review** on Scan Details now open a signing pop-up that asks for the user's password again (21 CFR 11.200(a)). The login is prefilled with the signed-in account, read-only, and checked on the server. A wrong password is written to the login log (`SignatureFailed`) and counts toward the account lockout; at the threshold the account is deactivated as on the Login page, the session ends and the user lands on the Lockout page. The signature reasons are unchanged ("Reviewed & Signed" / "Reopen review"); a "meaning of signature" choice is still to come.
- The AI backend is now configurable on the AI Analysis tab: provider (OpenAI, Azure OpenAI or Microsoft Foundry) and endpoint, so a customer can point analysis at an EU-hosted or private resource or an OpenAI-compatible gateway. A blank endpoint keeps `https://api.openai.com`, so existing installations are unaffected. A **Test connection** button on the tab sends a minimal request with the current, possibly unsaved, values and shows the result in a pop-up; nothing is saved or audit-logged by the test. Requires database scripts `ATR 0.33` and `ATR 0.35`.
- The Email tab can now store the SMTP user name and password (the password encrypted at rest and never shown or audit-logged), and has its own **Test connection** button that sends one test e-mail to the configured From address. Falls back field by field to `appsettings.json`. Requires `ATR 0.32`.
- **Export to Excel** buttons added to the Systems and Scans lists, System Details, Application Settings, the Rule-Based Review Engine, System Types, Users, Roles and the User login log. Scan Details' export now covers every tab (scan results, potential findings, AI analysis, signatures and a combined audit trail). The Scans table on System Details is now paged, 10 per page.
- Added `deploy/` scripts and an Azure DevOps pipeline (`pipelines/pipeline-deploy-on-azure-cloud.yml`) for a manual, per-customer deployment: builds and pushes the four images, applies the SQL schema scripts to Azure SQL, rolls out the Container Apps and runs a smoke test.

- **FTP settings moved into the application.** FTP ingestion is now configured on a new **FTP** tab (`Admin Panel → Application Settings`) instead of an `Ftp` section in the Worker Service's `appsettings.json`. The tab supports plain FTP, explicit FTPS and implicit FTPS, and the password is stored encrypted (AES-256-GCM, same `Security:EncryptionKey` as the other stored secrets). A master switch, **off by default**, controls whether the Worker Service polls at all. The Worker Service re-reads the settings on every polling cycle, so a change takes effect without a restart. One Worker Service instance ingests for exactly one system. **Requires `ATR 0.40`.** An `Ftp` section in an existing Worker Service `appsettings.json` is no longer read: re-enter the settings on the tab and switch it on.
- **MCP server query tools.** In addition to `list_systems` and `list_scans`, the MCP server now offers `get_scan_summary`, `get_scan_findings`, `query_scan_records` and `query_app_audit_trail`, all strictly read-only and capped at 200 rows per call.
- **Per-user MCP keys.** An admin can issue an MCP key to a specific WebApp user from the MCP tab; that key's calls are attributed to the user in the MCP server log. **Requires `ATR 0.39`.**
- **Validation package.** The Validation Package (`AuditTrailReview.Docs/Validation Package/`) gained functional tests FT-23 to FT-38 and the traceability gaps they close, so every requirement that can be tested now traces to a test (see `7 Traceability Matrix.md`).

### 🔧 Improvements

- Uploads are now capped at 786,432,000 bytes (750 MiB exactly) instead of the previous ~954 MiB ceiling, across the WebApp, the Integration Hub API, and the Console client. The "file too large" message on the upload page was also simplified to a short note that the file exceeds the system's 750 MB limit, instead of the previous detailed modal text.
- Sped up WebApp uploads of small files: the 19 audit-trail rule flags are now loaded in a single query instead of 19 separate sequential database round trips, so tiny files no longer take as long to upload as files with tens of thousands of records.
- Reopening a signed scan, deleting a scan, and deleting a system now each require an Admin or Super User account; previously any signed-in user (including User) could do all three. Review, sign-and-close, and creating/editing a scan or system remain open to every role.
- Application Settings and AI Analysis moved from **Config Panel** to **Admin Panel**, which is now Admin-only throughout (previously Admin or Super User for these). Super User's remaining configuration access is Config Panel's two other pages: Rule-based review engine and System type. See the in-app User Manual's "User roles" section for the full permissions matrix.
- Reordered the action icons on the Systems, Scans, System Types, and Users list pages to a consistent view → edit/link → delete left-to-right order, with Delete always last.
- The Rule-Based Review Engine and AI Analysis pages now use the full page width instead of being squeezed into a narrow centered column.
- Application Settings (`Admin Panel → Application Settings`) is now a single tabbed page -- General, Security, Email, AI Analysis, plus a shared Audit Trail tab -- replacing the previous read-only overview and its four separate edit pages, matching the tab pattern already used by the Rule-Based Review Engine page.
- Hardened WebApp and Integration Hub API responses: added Content-Security-Policy, `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, and `Cross-Origin-Opener-Policy` headers, removed the Kestrel `Server` header, and forced the Identity and antiforgery cookies to `Secure`+`HttpOnly`. Every page now requires authentication by default, so a page added later without an explicit `[Authorize]`/`[AllowAnonymous]` attribute fails closed instead of being silently reachable anonymously.
- Deleting a user account that has uploaded or queued a scan is now blocked (Delete button greyed out with an explanatory tooltip on `AdminPanel → Users`, and enforced server-side too), since doing so would orphan the new "Uploaded by" reference on Scan Details/Dashboard.
- The active tab in every tabbed page (Rule-Based Review Engine, Application Settings, and the other per-record "Audit Trail" tabs) is now easier to spot at a glance: a grey fill, bold label, and a colored underline, with a lighter hover state on the other tabs.
- Self-registration is switched off. `/Identity/Account/Register` and 16 other unused Identity pages (e-mail self-change, account self-deletion, personal-data download, external logins, two-factor setup) now answer 404, and `/Account/Manage` requires sign-in. Before this, anyone who opened the Register page got an account and was signed in at once. The Account menu shows only Profile and Password. **Before upgrading an existing installation, check for users with no role** (rows in `AspNetUsers` with no `AspNetUserRoles` entry): they may have been created through Register.
- The **Logs** menu and the two Log pages (user login log and audit trail log) are now limited to Admin and Super User; a plain User is sent to the Access denied page. The per-record "Audit trail" tabs are unchanged.
- The Error page is no longer the ASP.NET template. It shows a status-specific message, a *Reference* code and a link back to the Dashboard (or sign-in), and never shows exception or environment details. 404, 403, 400, 413 and other empty error responses use the same page. The Reference is the request's `CorrelationId` in `dbo.ApplicationLog`, so support can find the matching log entries. The unused template Privacy page was removed, since a privacy notice has to name the customer's own data controller and retention terms.
- Security policy changes (password rules, lockout, sign-in) now apply on the very next request; no application restart is needed. The old "pending restart" banners are gone.
- Assigning a system to a scan now requires Admin or Super User, in the UI and on the server. Assigning a system from the scan list also records the assigning user as the scan's user (`ScanInfo.UserId`, shown as "Uploaded by" and counted in the Dashboard's "My Latest 5 scans"), replacing any user previously recorded on that scan, such as the original uploader. The Engine Settings panel was removed from Scan Details, and the Manage account breadcrumbs follow the active tab. Dashboard quick-action buttons and the signing pop-ups gained icons.
- The shared encryption key setting is now `Security:EncryptionKey` (environment variable `ENCRYPTION_KEY` in the Docker flavor), since it protects the OpenAI key, the SMTP password and the API/MCP keys. **It was previously named `Security:AiApiKeyEncryptionKey` / `AI_API_KEY_ENCRYPTION_KEY`; rename it in existing deployments**, with the same value, or stored keys can't be decrypted.
- The in-app documentation chatbot ("Ask a question" page, its Admin Panel reindex page and the embeddings support behind it) was removed. The Help page's "Ask a question" button now links to the support site. **Requires `ATR 0.34`**, which drops `dbo.DocChunk`, `dbo.DocIndexStatus` and `AiSettings.EmbeddingDeploymentName`.

- **Docker Compose files moved to `docker/`.** `docker-compose.yml`, `docker-compose.postgres.yml` and `docker-compose.sqlite.yml` now live in the `docker/` folder. Run them from the repository root with `docker compose --project-directory . -f docker/<file> up`, so the build context, `.env` and `./backups` still resolve against the root. The compose project name is fixed (`gxpaudittrail`), so existing volumes are reused. Update any script or documentation that calls the old root-level file names.
- **Three Azure DevOps pipelines, renamed and documented.** The pipeline definitions are in `pipelines/`: `pipeline-ci-build-unit-test-dev-ops.yml` (build and unit tests on every push to `master`), `pipeline-ui-tests-external-env.yml` (manual Playwright UI tests against any running environment, URL and login given as run parameters) and `pipeline-deploy-on-azure-cloud.yml` (the deployment above). **Pipelines already registered in Azure DevOps must be pointed at the new YAML path**, otherwise runs fail with "file not found". See `CICD/Azure Pipelines.md`.
- The WebApp, Integration Hub API and Worker Service now reference `Microsoft.Data.SqlClient` 7.1.2 and `Microsoft.Data.SqlClient.Extensions.Azure` 7.1.2 directly, which the Azure deployment needs for managed-identity (Entra ID) login to Azure SQL. Connection strings for SQL Server and LocalDB are unaffected. See SBOM v0.9 for the resulting package list.
- Scan Details bulk review: the "By search" card was removed from the Bulk review sub-tab; the "By rule" card now uses the full width.
- **Documentation brought in line with the product (NFR-043).** The PRD's risk section no longer lists gaps that were fixed (role enforcement, server-side close-and-sign check, in-memory FTP list, secrets in source control, audit log scope, duplicated parsing) and its AI section says the provider, endpoint and model are configurable. UAT section 5 items 4 (extension allow-list) and 9 (correlation ID) are marked resolved, with items 2 and 11 refreshed. The FRS no longer specifies the removed Documentation Chatbot (FR-041 and FR-042 are retired; FT-13 now covers the Help pages and TC-501 was removed). ADR-0010 and the Technical Manual now state that the MCP server has a `/health` endpoint and is part of `docker/docker-compose.postgres.yml`. The Installation Manual, Technical Manual and ADR-0004 list every SQL script up to `ATR 0.40` and describe the incremental-script approach.

### 🐞 Bug Fixes

- Fixed AI analysis and the AI "Test connection" button failing with a 400 error on newer models such as `gpt-5-mini`, which reject the old `max_tokens` parameter; requests now send `max_completion_tokens`.
- Fixed a full URL typed into the AI Analysis tab's Endpoint field getting `/v1/chat/completions` appended twice. Choosing OpenAI as provider now prefills the endpoint.
- Fixed **Send Credentials** on Edit User showing an unhandled-exception page when the SMTP server rejects the message; it now shows a warning pointing to Application Settings → Email.
- Fixed the footer not staying at the bottom of the page in published and Docker builds: `site.css` was excluded from the published output and is now shipped with it.
- Fixed Scan Details loading slowly (tens of seconds, even for scans with as few as 37 rows) by adding a missing database index on `ScanResult`/`ScanResultAI`'s `ScanID` column; every Details page load, AI-analysis poll, and Excel export filters by `ScanID` and was forcing a full table scan across every scan ever ingested. Applied to SQL Server and to the SQLite/PostgreSQL demo flavor's EF model.
- Fixed the audit trail log (`Log → Audit trail log`, and the new per-record "Audit trail" tabs above) showing "Old value" as the header for both the old-value and new-value columns; the new-value column now correctly reads "New value".
- Fixed Edit User silently failing to save in a real browser: the form was missing fields for user ID/username/email that `ModelState` required, so every save on that page failed validation with no visible field error.
- Password reset emails are no longer sent to deactivated accounts; the same generic confirmation page is shown either way so account status isn't leaked.
- Removed an unlinked, unused scan-editing page (a leftover scaffold with no link anywhere in the app) that let any signed-in user overwrite any scan's fields directly, bypassing the audit trail.
- Fixed every form page (Login included) returning `500` when the WebApp runs behind a reverse proxy or tunnel that terminates TLS and forwards plain HTTP to the container -- this version's own `Cookie.SecurePolicy = Always` hardening (above) started throwing `AntiforgeryOptions... the current request is not an SSL request` in that deployment shape, since the container only ever sees plain HTTP. `Program.cs` now applies `UseForwardedHeaders` so a `X-Forwarded-Proto: https` header from the proxy is honored; see `CICD/Run docker compose on VPS.md` section 6.
- Fixed saving an OpenAI key from the AI Analysis tab's new "store the key in the database" option (above) failing with `500` on the PostgreSQL Docker flavor: `docker/docker-compose.postgres.yml` never set the encryption key (the AES-256-GCM master key `ApiKeyProtector` needs, now `Security:EncryptionKey`), so it fell back to the shipped `appsettings.json` placeholder, which isn't valid base64/32 bytes. The services now read it from the `ENCRYPTION_KEY` variable (gitignored `.env` file, see `.env.example`) instead of a value hardcoded in the compose file, since a working key is indistinguishable from a real secret to anything scanning the repository.

- The user login log no longer trusts a client-supplied `X-Forwarded-For` header. It records the connection's address, and forwarded headers are honoured only from the proxies in `ForwardedHeaders:KnownProxies` / `KnownNetworks` (default: loopback only; the compose files pass `TRUSTED_PROXY_NETWORK`). **If the WebApp runs behind a reverse proxy or tunnel, add its address or network**, otherwise the login log shows the proxy's address and form pages can fail with a `500` (see `CICD/Run docker compose on VPS.md` section 6).

### ⚠️ Known Issues

- The nightly backup is written to the same host as the database. Copy `./backups` off the host (scp/rsync); a backup on the same disk does not survive losing that disk.
- The `POSTGRES_PASSWORD` values in `docker/docker-compose.postgres.yml` are placeholders and must be replaced with a strong password (identically for the `postgres` and `backup` services) before any deployment beyond local trials.
- `AuditTrailReview.McpServer` `/mcp` requires an API key (generated from `AdminPanel -> Settings -> MCP`, header `X-Api-Key` or `Authorization: Bearer`) and is rate limited per IP (`McpRateLimiting`); `GET /health` is unauthenticated. The key is static with no per-user identity (see ADR-0010).
- Upgrading an existing installation drops both `IntegrationHub.API`'s and `McpServer`'s previously configured keys (`ApiKeyAuth:Keys`/`McpAuth:Keys` are removed from `appsettings.json`); every caller gets `401` until an admin generates a new key for each service from the new "API"/"MCP" tabs (above) and distributes it. Both services also need `Security:EncryptionKey` set to the same value as the WebApp's own -- without it, every key check fails regardless of the key presented.
