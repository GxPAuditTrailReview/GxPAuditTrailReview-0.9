# TC-703 – WebApp Admin Panel: Application Settings Audit Trail Tabs and AI Save Handler

## Objective
Verify the "Audit trail" tab's four sub-tabs (Security/General/Email/AI) on the consolidated Application Settings page (`Pages/AdminPanel/Settings/Index.cshtml.cs`'s `IndexModel`), each one scoped to its own `ConfigPanel` audit-trail `Object` value so that unrelated settings sub-tabs sharing the same `ObjectType` never leak into each other. `IndexModel` replaces what used to be four separate single-purpose pages (`EditAI`/`EditEmail`/`EditGeneral`/`Edit`, now deleted) with one tabbed page -- Security, General, Email, and AI Analysis each get an always-editable tab plus their own Audit Trail sub-tab. Also verifies `IndexModel.OnPostSaveAiAsync` specifically -- the AI tab's save handler, which stores the OpenAI API key encrypted (`AiSettings.ApiKeyEncrypted`, via `ApiKeyProtector`, TC-806) and restricts the chat model to `Engine.OpenAIService.AllowedChatModels` -- including that the key's ciphertext never reaches `dbo.AuditTrail`. Also verifies `IndexModel.OnPostSaveSecurityAsync` reloads `SecurityOptionsState` with the saved values in the same request (the live-reload mechanism, see `SecurityIdentityOptionsSetup.cs`, that replaced the former "restart the application" requirement -- `SecuritySettings`'s own doc comment and `AuditTrailReview.Docs/Validation Package/5 Configuration and Functional Testing - IQOQ.md`'s CT-06 have the full before/after). The Email tab's password handling and the FTP tab's save handler are covered by TC-706; the General tab's `OnPostSaveGeneralAsync` still has no unit test coverage.

**2026-11-05: absorbed `TC-753` (formerly `AdminPanel/AIEnhancedReviewEngine`, a standalone page).** That page's on/off toggle for the background AI-assisted scan analysis step (`EngineSettings.AiAnalysisEnabled`, ADR-0006, NFR-014) and its read-only display of the exact prompt template (`AuditTrailPromptBuilder.DescribeTemplate`, TC-510) were merged into this page's AI Analysis tab, saved together with `AiSettings` by the same `OnPostSaveAiAsync` handler (via a new `SaveAiAnalysisEnabledAsync` helper). The AI sub-tab's Audit Trail query now also includes this toggle's own history (`EngineSettings`/`AiAnalysisEnabled`, alongside `AiSettings` changes), and the Excel export's AI Analysis sheet gained matching "AI Analysis Enabled"/"Prompt Template" rows. `TC-753` is deleted; see its own steps 20-30 below and this TC's Change history.

## Preconditions
- `IndexModel` is constructed with an EF Core InMemory `ApplicationDbContext`, a real `AuditTrailService` (TC-801), an `IConfiguration` (empty for the `OnGetAsync` audit-trail tests; one seeded with a valid base64 32-byte `Security:EncryptionKey` for the `OnPostSaveAiAsync`/`OnPostSaveEmailAsync` tests that call `ApiKeyProtector.Encrypt`), a `SecurityOptionsState` (a fresh `new SecuritySettings()` by default, or one the test constructs itself to inspect after a Security-tab save), and a `DateTimeDisplayService` (TC-804).
- `PageModelTestHelpers.InitializePageContext` wires up a signed-in user, and (as of this test class) also registers a real `IObjectModelValidator` (via `AddMvcCore()`) in `PageModel.HttpContext.RequestServices`, since `OnPostSaveAiAsync` -- like every other `OnPostSave*Async` handler on this page -- calls `TryValidateModel`, which the Audit Trail-only tests never exercised before.

## Assertions
- `OnPostSaveSecurityAsync` calls `SecurityOptionsState.Reload` with the just-saved `SecuritySettings` in the same request that writes them to the database, for both the create (no existing row) and update (existing row) branches -- this is what makes a Security tab save take effect immediately, replacing the former `IOptions<IdentityOptions>`-bound-once-at-startup/restart-required behavior.
- The session settings (idle timeout, maximum session length, sign-out warning) are saved, audited and reloaded like the rest of the Security tab, and a save whose warning is not shorter than the idle timeout, or whose idle timeout exceeds the maximum session length, is rejected without changing anything.
- Each of the four Audit Trail sub-tabs (Security/General/Email/AI) includes only entries for its own `Object` value, even though all four, plus the Config Panel rule engine and System Type pages, log under the same `AuditObjectType.ConfigPanel`.
- Each sub-tab supports search filtering and paging independently via the shared `LoadAuditTrailSubTabAsync` helper.
- `OnPostSaveAiAsync` stores the OpenAI API key only as `ApiKeyProtector`-encrypted ciphertext, never plaintext; a blank key field preserves the existing key, and `ClearApiKey` is the only way to remove it.
- `AiSettings.Model` is rejected server-side (not just by the `<select>`) when it falls outside `OpenAIService.AllowedChatModels`.
- The API key's ciphertext is never written to `dbo.AuditTrail` under any field name, in any save (create, update, key-only change, or key alongside other field changes), while a key-only change still produces exactly one traceable (but non-reversible) audit entry.
- The AI-assisted scan review toggle (`EngineSettings.AiAnalysisEnabled`) persists correctly whether or not an `EngineSettings` row already exists, is saved together with `AiSettings` by the same `OnPostSaveAiAsync` handler without a separate submit, and audit-logs only genuine changes, never touching unrelated `EngineSettings` fields (mass-change thresholds, workday time zone, etc.; see TC-752).
- The displayed prompt template always matches what `AuditTrailPromptBuilder` actually builds.
- The AI sub-tab of the Audit Trail tab combines `AiSettings` changes and the toggle's own `EngineSettings`/`AiAnalysisEnabled` changes into one scoped, searchable, paginated view -- a C3/D1/D2/E1 threshold change logged against the same `EngineSettings` row by TC-752's "Engine Settings" tab must not appear here.
- The Excel export's AI Analysis sheet and combined Audit Trail sheet both reflect the toggle and its history, consistently labeled alongside the rest of the AI Analysis tab's content.

## Notes
- The General/Email tabs' own `OnPostSave*Async` handlers remain untested here -- only `OnPostSaveAiAsync` and (as of this revision) `OnPostSaveSecurityAsync` are exercised.
- `OnPostSaveSecurityAsync`'s test only verifies `SecurityOptionsState.Reload` is called with the saved values -- it does not exercise the live `IOptionsMonitor<IdentityOptions>` reload path itself (that `IdentityOptions.Password`/`Lockout`/`SignIn` actually change for the next `UserManager`/`SignInManager` constructed), since that crosses into ASP.NET Core Identity's own DI wiring, which InMemory-backed page-model unit tests don't exercise. That end-to-end behavior is covered manually by IQOQ CT-06 (`AuditTrailReview.Docs/Validation Package/5 Configuration and Functional Testing - IQOQ.md`), not by an automated test.
